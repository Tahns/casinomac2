### Done
1. **Baseline first (A4).** Before any change: `tests/audio/baseline_render.mjs --write` rendered 62 cases with the v1 engine in an OfflineAudioContext (every v1 cue and option set, both beds, two mixed scenes; overall rms, peak and a per-window rms envelope in dBFS) into `tests/audio/fixtures/baseline_v1.json`. Committed alone (381db51). `--check` re-renders and compares at 0.001 dB: the render is bit-stable run to run.
2. **Buses.** `sfxBus` and `musicBus` feed `master -> compressor -> soft limiter`; a `duck` gain sits between `musicBus` and `master`. `sfx` (0.9 trim), the effects reverb return and the effects spring go to `sfxBus`; the bed's mood bus, its reverb return and its spring go to `musicBus`. **Two reverb returns:** one impulse buffer, two convolvers (`verb`/`verbSend`/`vo` for effects, `verbM`/`verbSendM`/`voM` for the bed). `tone()` and `noise()` pick the send by their `bed` flag. The random-number order of the engine is unchanged (the impulse is built once, the noise buffer after it), so every noise cue is bit-identical to v1.
3. **Levels.** Master target = `mute ? 0 : 0.8 * taper(master)` (one place, the old duplicated 0.8 is gone). All three gains use `cancelScheduledValues` + `setTargetAtTime(g, t, 0.03)`; mute keeps the v1 constant 0.02. A target of exactly 0 is followed by a `setValueAtTime(0, ...)` so the node lands on true silence. Engine option `volumes:{master,music,sfx}` sets the start values without a ramp (the live engine is created with the stored values).
4. **Taper** (`taper(s)`, `taperDb(s)` exported): 0 -> 0, 1..75 -> -45..0 dB linear in dB, 75..100 -> 0..+3 dB. 75 is unity, so the defaults ARE today's mix. Table: 1 = -44.4 dB, 25 = -30, 50 = -15, 60 = -9, 100 = +3.
5. **Zero handling = nothing is queued.** The engine refuses new voices for a bus that cannot be heard (`audible(bus)`: not muted, Master > 0, and the bus slider > 0) inside `tone/noise/roll/boing/trombone`, so offline and live behave the same. Live: `audio.play` returns false for effects while Effects or Master is 0 or when muted; the bed scheduler releases the bed when Music or Master is 0 or when muted and restarts it on a bar line when raised (`applyMood`).
6. **Mute stays the single source of truth.** `am_muted` is written only by `audio.setMuted`. `body.muted` and `#btn-sound[aria-pressed]` show **silent** (= muted, or Master 0, or Music and Effects both 0) so the header speaker never lies; `audio.muted` is still the pure mute flag. New `audio.silent`, `audio.toggleMute()` (what `#btn-sound` should call: unmute, or restore the last non-zero sliders when the sliders made it silent, or mute), `audio.lastVolume(kind)` (memory only, nothing extra is stored), `audio.resetVolumes()`. `onChange` events now also carry `silent`.
7. **Preview.** `audio.preview(kind)` plays the `settingsTest` cue (low bongo + one vibraphone note A4, no chime, no coin or bell timbre) on the bus being tested: Effects slider -> effects path, Music slider -> music bus, Master slider -> straight into `master` (dry, so it reflects Master alone). Rate limit 250 ms on the audio clock inside the engine (`CUE_INFO.settingsTest.minGap`), so `audio.play('settingsTest')` is limited too. Silent while muted or while that bus is at 0. Same loudness on the three paths (test).
8. **Cues and `winLike`.** `CUE_INFO` (exported, frozen) has an explicit boolean `winLike` for EVERY sound (a test pins that the table and `SOUNDS` have the same keys). Ten new cues: `ledgerTick` (quiet adding-machine key, about -22 dBFS peak), `settingsTest`, `caseSeal`, `caseOpen`, `lightsOut`, `spotlightStep` (alternates two pitches, never a rising scale; option `i`), `layoutDraw` (pencil strokes stepped at 12/s, `dur` 0.15..0.5 s, default 0.45), `doorCreak` (`dur` 0.3..1.1 s, default 0.9, always under the 1.2 s rule), `dialStep` (ratchet, `n` 1..4 clicks); `stamp` already existed in v1 and is kept bit-exact at its defaults (options `vol`, `pitch` added). All ten are winLike false.
   - **Quiet-result path:** `audio.play(id, { quiet: true })` refuses (returns false, creates no node) every cue whose flag is true. WP4 must pass `quiet: true` for every cue on the R <= C path (or call only `ledgerTick`). `audio.isWinLike(id)` and `audio.cueInfo(id)` are there for callers.
   - Flag policy: winLike = could be taken for a win, a payout or a reward: tonal fanfares, rising vibraphone notes, coins, bells, cymbal swell. When in doubt true. True: win xylo scatter dossier pop (pitch climbs with the combo) defuse (ends on a rising triad) vault (ends on a bell) mult meterTick meter metermax meterRise riser fsStart retrigger fsEnd tada bigwin kaching coin shower stinger drip. False: click error nearmiss wahwah spin whoosh land antic wire fuse tick ticks snip explosion blast stamp phone shutter count heart rumble crack mascot_hop mascot_gasp and the ten v2 cues.
   - Unknown, non-string and prototype ids are no-ops at engine and API level.

## Decisions
- `winLike` is conservative (true when in doubt), because a wrong false is a compliance miss and a wrong true only costs a sound on the quiet path.
- `pop` is win-like (the climbing pizzicato is a reward ladder): the quiet path uses `ledgerTick` only.
- The header speaker mirrors "silent", the Mute switch mirrors `audio.muted`; they differ only when a slider made the game silent. WP1 should call `audio.toggleMute()` from `#btn-sound` and read `audio.muted` / `audio.silent` instead of keeping `S.muted` (request file written).
- The rate limit is on the audio clock (not wall time) so it is testable offline and cannot be fooled by a stalled context.
- Ducking is off by default (engine and live); it is implemented and tested, the switch is `audio.duck = true` (or `DUCK_DEFAULT`), to be flipped after a human has listened.

- `body.muted` is also toggled by `main.js` (`btn-sound` handler) in v1; until WP1 switches to `toggleMute()`, a slider-made silence and the handler can disagree on the icon.
